# Multiplayer Race — Design Foundation

Status: **engine and server built, client not yet started.** The race rules
live in `lib/engine/race.ts` and the authoritative server in `server/` (a
Cloudflare Worker plus one Durable Object per room), both with test coverage.
This document captures the decided rules, the architecture for the head-to-head
"live race" mode, and how the rest of the codebase has been prepared for it.

## The game mode

Two (or more) players race on the **same seeded country sequence**:

- Room settings pick a country set (all, or a continent) and a count. The
  seeded shuffle takes the first N (`RACE_CONFIG.countryCount`, default 20).
- Both players see the same prompt at the same time.
- **Claim mechanic:** the first player to correctly click the current country
  *claims* it. They score one point, the country resolves for everyone, and
  after a short intermission the race rolls over to the next country.
- **Country window:** each country is on screen for a fixed window
  (`countryWindowMs`, default 10s). If nobody claims it, it resolves
  *unclaimed* with no owner and the race moves on.
- **Wrong clicks cost time, not tries:** a wrong click locks that player out
  for `lockoutMs` (default 1.5s). Clicks while locked are ignored and do not
  extend the lockout. The lockout is wall-clock, so it carries across a
  rollover. Clicking an already-resolved country is a free click.
- **Scoring:** one point per claim. Ties are broken by total claim time (the
  sum of "country shown → claimed" across a player's claims; lower wins).
- **Leaving:** a disconnected player keeps their claims and can no longer
  claim. The race continues for everyone else and finishes early only when
  nobody is left connected. Rejoining restores the player.
- End screen shows who claimed which countries and the fastest claims.

## Architecture

```
apps/web (this repo)                 server/ (Cloudflare Worker)
┌──────────────────────────┐   WS    ┌──────────────────────────────┐
│ React / R3F globe        │◄───────►│ Worker: room ids, WS upgrade │
│ zustand adapter stores   │         │   └─ RaceRoom (Durable Obj)  │
│ lib/engine (shared)      │         │      - lib/engine (same code)│
└──────────────────────────┘         │      - storage alarm = clock │
                                     └──────────────────────────────┘
```

- **Authoritative server.** The server owns the RNG seed, the country order,
  claim resolution (first valid `guess` wins; the server's processing order
  decides ties), and all scoring. Clients render state and send intents; they
  never decide outcomes. This is what makes the mode cheat-resistant: the
  client only ever says "I clicked country X" and the server validates it
  against its own state and clock.
- **Rooms.** One Durable Object per match, addressed by `idFromName(roomId)`.
  That *is* the room registry: every player of a match lands on the same
  instance with no lookup table and no sticky routing. A room only comes into
  existence through `POST /api/rooms`, which mints the code and calls `open()`
  on the object; a socket to an unopened code is answered with `no_such_room`
  rather than creating one. So every code in play was generated by the server
  — nobody picks a vanity code, squats someone else's, or makes rooms without
  passing the rate limiter. Shared via invite link (`/race?room=CODE`);
  matchmaking can come later.
- **Why Durable Objects.** A DO runs single-threaded, so two simultaneous
  claims serialise and the first processed wins — the tie-break the engine
  already assumes, for free. `phaseDeadline` becomes a storage alarm, which is
  durable across eviction, so there is no long-lived process to keep alive.
  Between alarms the object hibernates with its sockets open, so an idle room
  costs nothing. Workers pin `Date.now()` between I/O, which is harmless here
  because every engine call is triggered by a socket message or an alarm and
  takes `now` as a parameter — the engine never polls.
- **Lobby.** Pre-race seating, ready flags, host role and room settings live in
  `server/src/lobby.ts` as pure transition functions with the same
  same-reference-means-no-op contract as `lib/engine` (tests:
  `server/test/lobby.test.ts`). The Durable Object only moves bytes, persists
  state, and keeps time.
- **Shared rules.** `lib/engine` is deliberately pure, deterministic, and
  JSON-serializable so the same code runs on both sides. The race rules live
  beside the solo rules in `lib/engine/race.ts` and follow the same pattern:
  `applyX(state, input, now) → state`, same reference for a no-op.

## Engine model (`lib/engine/race.ts`)

Phases: `countdown → racing ⇄ intermission → finished`.

Every phase that ends on its own exposes that moment as `phaseDeadline`
(`startsAt` in countdown, the window end while racing, the next reveal in
intermission, null once finished). That single field is the only clock the
server has to watch: sleep until `nextTransitionAt(state)`, then call
`tick(state, now)`.

| Function | Role |
|---|---|
| `createRace(countryIds, config, seed, players, startsAt)` | Shuffle, slice to N, start the countdown. Players are fixed here; the lobby lives in the server. |
| `tick(state, now)` | Apply every due deadline. Uses the real `now` for each step, so an oversleeping server resolves the missed country and re-times the next phase from the present instead of cascading. |
| `guess(state, playerId, countryId, now)` | Settles due deadlines first, then claims or locks out. A late guess is always judged against the state as of `now`. |
| `leave` / `rejoin` | Connection flags; finishes the race when nobody is left. |
| `standings(state)` | Players by claims desc, total claim time asc, id. Position 0 leads. A draw is two players equal on both; the engine does not declare a winner. |
| `nextTransitionAt`, `timeRemainingMs` | Read-only clock helpers for the server timer and the client timer bar. |

Defaults live in `RACE_CONFIG` (`lib/constants.ts`). The engine never reads
them; whoever creates the race passes them in, so rooms can override.

## Protocol (v1)

Defined in `server/src/protocol.ts`; client frames are parsed defensively and
an unreadable frame is dropped rather than throwing.

Client → server:
- `join { name, playerId? }` — `playerId` re-claims a seat after a reload
- `ready { ready }`
- `configure { countrySetId?, countryCount? }` — host only, lobby only
- `start {}` — host only, validated against `canStart`
- `guess { countryId }`
- `ping {}`

Server → clients:
- `welcome { playerId, roomId, serverNow }` — sent once per connection; the
  `playerId` is the reconnect credential
- `lobby { lobby, canStart, serverNow }`
- `state { state, serverNow }` — full `RaceState` after every accepted event
- `finished { state, standings, serverNow }`
- `error { code, message }`, `pong { serverNow }`

Two properties worth keeping: state is broadcast **whole**, not as deltas, so
reconnection is a no-op — a rejoining client gets the same message everyone
else does. And every timing message carries **`serverNow`**, because all
deadlines are absolute epoch ms; a client with a skewed clock corrects with
`offset = serverNow - Date.now()` measured on receipt.
